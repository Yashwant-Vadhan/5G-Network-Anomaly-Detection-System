### Protocol for AI coding agents (read this before touching code)
1. Read `project-overview.md` (source of truth) and the **Guardrails** table in `docs/planning/TECH_RULES.md`. If anything conflicts, the overview wins.
2. Pick **one** task: the first `⬜` task, in ID order, whose **Dependencies are all ✅**, belonging to the **Owner you are assisting**. Skip `🧑 Human-only` and `➕ Optional` tasks unless told otherwise.
3. Do only what the task says. Touch only the files it names (plus their tests). Do not refactor other modules.
4. Write the tests listed in the task or in the matching Phase 7 task. Run `make lint test`. Do not mark ✅ until tests pass (G16).
5. Never fabricate measurements, never impute missing radio values, never treat `NA` as 0, never infer SA from `UNKNOWN`, never label a weak signal or a PCI/NCI change as an anomaly on its own, never use synthetic data as real data, never add an LLM to the core decision path.
6. If a task contains `⚠️ UNCLEAR` or you find an ambiguity, **stop and ask the human**; record the answer in `docs/eda_findings.md` or `docs/decisions.md`.
7. Commit as `type(T#-###): message`, branch as `feat/<owner>/T#-###-slug`, open a PR, and have the *other* teammate review.
8. When done: change the task's status to ✅ and tick its acceptance boxes in the same PR.

### Non-negotiable rules (from overview §56)
Keep collector and ML separate · never fabricate measurements · `NA` = missing · never infer SA from UNKNOWN · not every weak signal is an anomaly · not every PCI/NCI change is an anomaly · preserve raw data · reproducible preprocessing · ML detection separate from agent explanation · document assumptions · use real data · label synthetic data · avoid unnecessary LLM dependence · clear agent responsibilities · tests for every major component · no "implemented" claim before tested.

### Task format
Each task: **Description · Dependencies · Acceptance Criteria (checkboxes) · Estimated Effort · Assigned To (role) · Owner (person) · Status**. Effort is 15–90 minutes of focused work (data-collection tasks include capture time).

### Notes on phase structure
The generic task template assumes a database, authentication and a web backend. This project has none of those (file-based batch pipeline + local Streamlit dashboard), so Phases 2–3 were adapted to *Data Collection* and *Preprocessing & EDA*. Security is still covered (CSV validation, PII rejection, secrets hygiene, localhost binding — T1-002, T1-008, T6-009, T7-009); authentication, rate limiting and HTTPS are recorded as **N/A by design** (T2-015, T7-009).
